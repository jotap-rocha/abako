RAG, LEDGER e Busca Híbrida

Recuperação de informação: quando vetorial, quando exato, quando híbrido

RAG LEDGER Vetorial BM25 Híbrido

"O modelo não leu o manual da empresa. Você precisa levar o contexto até ele — e a forma como você faz isso determina a qualidade da resposta."

O Problema

LLM não sabe de documentos privados

LLM treinado ate Ago 2025

Nao sabe de manuais internos, politicas atualizadas, dados da empresa, nem do que aconteceu ontem.

🌐

MCP

Web publica, docs de bibliotecas

Context-7 Exa

FastAPI docs, NumPy, LangChain — sempre atualizados via MCP, nao indexe no Qdrant.

📄

RAG

Docs privados, textos narrativos

Qdrant vetorial

Politicas internas, manuais, FAQs, e-mails de suporte — texto em que o significado importa.

🗄️

LEDGER

Dados exatos, fatos estruturados

SQL / KV

Precos, IDs, saldos, prazos — respostas unicas que nao toleram alucinacao semantica.

Regra de ouro

Escolha o canal antes de codificar. Canal errado = resposta errada mesmo com modelo perfeito.

Banco Vetorial

O que VAI e o que NAO VAI no vetor

Vai no vetor

  • Narrativas, manuais, politicas internas
  • E-mails de suporte e atendimento
  • Transcricoes de calls e reunioes
  • FAQs em texto corrido
  • Descricoes de produto (texto longo)
  • Artigos, relatorios, documentos PDF

Textos em que a proximidade semantica e o criterio de busca.

NUNCA vai no vetor

  • IDs, precos, CPF, CNPJ
  • Datas, timestamps, periodos
  • Saldos, contadores, quantidades
  • Status enums (ativo/inativo)
  • Tokens de autenticacao
  • Versoes de software (v2.3.1)

Dados exatos precisam de busca exata — SQL retorna o certo; vetor retorna o "parecido".

# ERRADO: preco no vetor
chunks = qdrant.search(
    query_vector=embed("R$ 149,90"),  # semantica de numero = ruido
    limit=5
)
# resultado: produtos "parecidos semanticamente" — nao o preco exato

# CORRETO: preco no LEDGER
row = cursor.execute(
    "SELECT preco FROM produtos WHERE sku = %s",
    [sku]
).fetchone()
# resultado: R$ 149,90 — exato, verificavel, auditavel
Arquitetura RAG

Pipeline de ingestao e pipeline de query

INGESTAO (offline — seed/, nunca no runtime)

Fonte→ Loader→ Chunker ≤512 tok→ Embedder→ Qdrant + Metadata

Metadata obrigatoria: source · section · date · type · tenant_id · content_hash

QUERY (runtime — backend/agent/)

Pergunta→ [Clean/Expand?]→ Embed→ Pre-filter→ Search→ [Rerank?]→ Context→ LLM→ Resposta + Fontes
Chunking

Recursive text splitter. Alvo: 256–512 tokens. Overlap: 10% do chunk. Nunca quebre sentencas no meio.

Embedding

text-embedding-3-large — 3072d, qualidade maxima. Mesmo modelo em ingestao e query (invariante absoluto).

Pre-filter

tenant_id obrigatorio. Nunca retorne dados de outro tenant por proximidade semantica — isso e uma falha de seguranca.

Padrao LEDGER

Busca exata: o livro-razao do agente

"LEDGER = livro-razao. Cada entrada e precisa, unica, verificavel. Voce nao pergunta 'o que e parecido com R$ 149,90' — voce pergunta 'qual e o preco do SKU-42'."

Two-query pattern

# Pergunta: "politica de devolucao e qual o prazo?"

# Step 1: RAG → narrativa
chunks = qdrant.search(
    query_vector=embed("politica devolucao"),
    query_filter=Filter(must=[FieldCondition(...)])
)

# Step 2: LEDGER → dado exato
prazo = cursor.execute(
    "SELECT prazo_dias FROM config WHERE tipo=%s",
    ["devolucao"]
).fetchone()

# Step 3: LLM combina com grounding obrigatorio
resposta = llm.invoke({
    "narrativa": chunks,
    "prazo_exato": prazo["prazo_dias"]
})
Busca Hibrida

Dense + BM25: semantica e exatidao lexical

Pure semantic falha para...

  • Siglas e codigos: M8, SKU-4291
  • Nomes proprios e marcas
  • Versoes e numeros de release
  • Termos tecnicos raros no corpus

Hibrido resolve porque...

  • BM25 acerta tokens exatos: M8 → docs com "M8"
  • Dense captura sinonimos e contexto
  • RRF funde os rankings sem tunar pesos
  • Melhor recall em vocabularios tecnicos

RRF — Reciprocal Rank Fusion

score(d) = 1/(k + rank_dense(d)) + 1/(k + rank_bm25(d)) — onde k=60 e o padrao. Nao exige calibrar pesos; documentos bem ranqueados em ambos sobem naturalmente.

# Qdrant sparse + dense (simplificado)
results = client.query_points(
    collection_name="produtos",
    prefetch=[
        Prefetch(query=dense_vector, using="dense", limit=20),
        Prefetch(query=sparse_vector, using="sparse", limit=20),
    ],
    query=FusionQuery(fusion=Fusion.RRF),
    limit=5,
)

Invariante absoluto

Use exatamente o mesmo modelo na ingestao e na query. Modelos diferentes geram espacos vetoriais incompativeis — a busca retorna lixo sem erro aparente. Registre o modelo no metadata de cada colecao.

Overlap entre chunks

Use 10% do tamanho do chunk como overlap (ex.: 512 tok → 50 tok de overlap). Garante que frases na fronteira entre chunks sejam recuperadas por ambos.

Metadata e filtros

Indexe os campos de filtro (tenant_id, type, date) como payload indexes no Qdrant. Pre-filtragem e ordens de magnitude mais rapida que pos-filtragem.

Tecnicas Avancadas

HyDE, Reranking e Multi-Query

HyDE

Hypothetical Document Embedding

Query curta → LLM gera resposta hipotetica → embeda a resposta (nao a query). O espaco vetorial da resposta e mais proximo dos documentos reais.

Use quando: queries informais, colecao formal/tecnica
Custo: +1 LLM call (~300ms)

Reranking

Cross-Encoder pos-retrieval

Top-20 candidatos → Cohere/cross-encoder → Top-3 precisos. O reranker ve query e documento juntos — muito mais preciso que cosseno.

Use quando: colecao > 10k docs
Tools: rerank-multilingual-v3.0, cross-encoder local

Multi-Query

Query Expansion

1 pergunta → LLM gera 3 reformulacoes → 3 buscas paralelas → RRF merge. Cobertura muito maior com vocabulario diverso.

Use quando: query ambigua, vocabulario diverso
Custo: +1 LLM call + 2 searches extras

Por que regras valem mais que documentacao

A regra RAG-01 impede que o agente coloque preco no vetor antes de codificar. A regra RAG-03 garante que tenant isolation nunca dependa de semantica — e portanto nunca vaza entre tenants por similaridade. Boas regras eliminam classes inteiras de erro antes que acontecam. Documentacao descreve o passado; regras governam o futuro.
