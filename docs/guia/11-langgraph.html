LangGraph Determinístico

Grafos, state, tools e human-in-the-loop

StateGraph Roteamento Tools Grounding Human-in-the-loop

"O LLM decide o que fazer dentro de um nó. O grafo decide para onde ir. Nunca confunda as duas responsabilidades."

O Problema

Por que não usar ReAct livre?

ReAct livre — loop LLM

LLM raciocina → chama tool
observa resultado → LLM raciocina...

Loop continua ate o LLM decidir parar — ou nao parar.

  • Nao-determinismo: mesma entrada, caminhos diferentes
  • Loop infinito: sem limite de iteracoes garantido
  • Custo imprevisivel: tokens ilimitados por run
  • Dificil auditar: trace nao reflete logica do produto

Grafo Determinístico

entrada → [classify] → route()
[run_sql] ou [search] → [generate] → END
  • Determinístico: logica de rota em codigo puro
  • Sem loop: cada nó executa uma vez
  • Custo previsivel: N chamadas LLM por design
  • Auditavel: trace reflete o grafo exatamente

Regra LG-01

O LLM decide dentro de um no. O codigo decide qual no vem a seguir. A fronteira entre os dois é o invariante mais importante do sistema.

Anatomia

Estrutura de um StateGraph

from langgraph.graph import StateGraph, END

# 1. Instanciar com o schema de state
graph = StateGraph(AgentState)

# 2. Registrar nos
graph.add_node("classify", classify_node)
graph.add_node("run_sql",  run_sql_node)
graph.add_node("search",   search_node)
graph.add_node("generate", generate_node)

# 3. Entry point
graph.set_entry_point("classify")

# 4. Edge condicional (logica no codigo)
graph.add_conditional_edges(
    "classify", route, INTENT_MAP
)

# 5. Edges diretas para o final
graph.add_edge("run_sql",  "generate")
graph.add_edge("search",   "generate")
graph.add_edge("generate", END)

# 6. Compilar (valida o grafo)
app = graph.compile()

Fluxo de execucao

entrada do usuario ↓ [classify] — LLM ↓ route()
[run_sql] | [search]
↓ [generate] — LLM ↓ END

Conceitos-chave

add_node — registra funcao Python como no

add_edge — transicao direta (sempre)

add_conditional_edges — rota por codigo

compile() — valida e retorna runnable

State Schema

TypedDict tipado com reducers

from typing import Annotated, Literal
from typing_extensions import TypedDict
from langgraph.graph.message import add_messages
from langchain_core.messages import BaseMessage

class AgentState(TypedDict):
    # reducer: lista acumula, nao substitui
    messages: Annotated[list[BaseMessage], add_messages]

    # campo simples: substitui a cada nos
    intent:   Literal["sql", "search", "hybrid"]
    query:    str
    sources:  list[dict]   # grounding obrigatorio
    answer:   str

Anti-padrao

Nao use dict genérico como state. Sem TypedDict voce perde type-check, autocompletion e a garantia de que todos os nos concordam com o contrato.

Campo Tipo Quem preenche Razao
messages list + reducer todos os nos historico acumulado
intent Literal classify entrada do router
query str entrada pergunta normalizada
sources list[dict] run_sql / search grounding obrigatorio
answer str generate resposta final

Reducers

add_messages acumula o historico em vez de substituir. Campos sem reducer sao sobrescritos a cada atualizacao — comportamento padrao e correto para intent/query/answer.

Roteamento

O LLM classifica. O código decide.

# Mapa de intencoes — imutavel, em codigo
INTENT_ROUTING = {
    "sql":    "run_sql",
    "search": "search",
    "hybrid": "run_sql",   # sql primeiro
}

# Funcao de rota: codigo puro, sem I/O
def route(state: AgentState) -> str:
    intent = state["intent"]
    return INTENT_ROUTING.get(intent, "search")

# Mapa de nos para add_conditional_edges
INTENT_MAP = {
    "run_sql": "run_sql",
    "search":  "search",
}

# Ligacao no grafo
graph.add_conditional_edges(
    "classify",   # no de origem
    route,         # funcao que retorna chave
    INTENT_MAP,    # mapa chave → no destino
)

Separacao de responsabilidades

LLM (no classify)

Le a query e escreve "sql", "search" ou "hybrid" no state

↓

Codigo (route)

Le o campo do state e retorna o nome do no. Sem LLM. Sem I/O. Determinístico.

Anti-padrao

Nao deixe o LLM retornar qual funcao chamar como string livre. Um enum tipado (Literal) com mapa de codigo e auditavel e seguro.

Design de Tools

Tools parametrizadas por nó — factory pattern

# Factory: parametros fixos fechados no closure
def make_sql_tool(
    engine, allowlist: set[str], limit: int = 500, timeout: int = 10
):
    async def run_sql(query: str, table: str) -> list[dict]:
        if table not in allowlist:
            raise ValueError(f"tabela nao permitida: {table}")
        safe = f"SELECT * FROM negocio.{table} WHERE {query} LIMIT {limit}"
        async with asyncio.timeout(timeout):
            return await engine.fetch_all(safe)
    return run_sql

# Factory: pre-filtro de tenant antes do semantico
def make_search_tool(qdrant, collection: str, tenant_id: str):
    async def search(query_vector: list[float], k: int = 5) -> list[dict]:
        # PRIMEIRO filtro exato, DEPOIS semantico
        filt = Filter(must=[FieldCondition(
            key="tenant_id", match=MatchValue(value=tenant_id)
        )])
        return await qdrant.search(collection, query_vector, limit=k, query_filter=filt)
    return search
Tool Params fixos Params da query
run_sql engine, allowlist, limit, timeout query, table
search qdrant, collection, tenant_id query_vector, k

Por que factory?

Parametros de seguranca (allowlist, tenant, limit) ficam fechados no closure — o LLM nao pode sobrescreve-los. Ele so passa os parametros da query. Surface de ataque minima.

Anti-padrao

Nunca deixe o LLM montar o SQL livre. Sempre allowlist de tabelas + LIMIT + timeout no closure.

Human-in-the-loop

interrupt_before + MemorySaver

from langgraph.checkpoint.memory import MemorySaver
from langgraph.graph import StateGraph, END

checkpointer = MemorySaver()

app = graph.compile(
    checkpointer=checkpointer,
    interrupt_before=["execute"],  # pausa ANTES do no
)

# 1. Invocar — pausa antes de "execute"
config = {"configurable": {"thread_id": "run-42"}}
state = app.invoke({"query": query}, config)

# 2. Mostrar plano para aprovacao humana
plan = state["plan"]
print(f"Plano: {plan}")

# 3. Usuario aprova (ou rejeita)
approved = input("Aprovar? (s/n): ") == "s"

# 4. Retomar — None continua do checkpoint
if approved:
    result = app.invoke(None, config)  # retoma
else:
    app.update_state(config, {"cancelled": True})

Quando usar

  • Acoes irreversiveis (write, send)
  • Execute em banco de dados
  • Envio de e-mail ou notificacao
  • Operacoes financeiras
  • Deploy em producao

Fluxo

invoke(input) ↓ pausa get_state → mostra plano ↓ humano decide invoke(None) → retoma ↓ END
Grounding

Toda resposta cita fontes — sem exceção

# No generate: fontes sempre no state
def generate_node(state: AgentState) -> dict:
    sources = state["sources"]
    if not sources:
        raise ValueError("LG-04: sources vazio — grounding faltando")

    context = "\n\n".join(
        f"[{i+1}] {s['content']}" for i, s in enumerate(sources)
    )

    prompt = ChatPromptTemplate.from_messages([
        ("system", """Voce e um assistente analitico.
Responda APENAS com informacoes do contexto abaixo.
Se a informacao nao estiver no contexto, diga
'Nao encontrei essa informacao nas fontes disponíveis.'
Nao invente dados, numeros ou fatos.

Contexto:
{context}"""),
        ("human", "{query}"),
    ])
    answer = llm.invoke(prompt.format(context=context, query=state["query"]))
    return {"answer": answer.content, "sources": sources}

Invariante LG-04

sources nao pode ser vazio ao entrar no no generate. Gere excecao em vez de deixar o LLM inventar.

Consequencias

sem grounding

Alucinacao nao auditavel — impossivel rastrear erro

com grounding

Resposta tracavel — cada afirmacao ligada a fonte

Campos obrigatorios em sources

content — texto da fonte
origin — tabela ou colecao
score — relevancia (search) ou confianca (sql)

Invariantes

LG-01 a LG-05 — regras que nunca quebram

ID Nome Regra O que proibe
LG-01 Grafo determinístico O LLM decide dentro de nos. O codigo decide qual no vem a seguir. ReAct livre, loop LLM sem limite, LLM escolhendo proximo no por nome
LG-02 TypedDict State schema tipado com TypedDict. Reducers declarados explicitamente. dict genérico, campos sem tipo, reducers implicitos
LG-03 Tools parametrizadas Parametros de seguranca fechados no closure via factory. LLM passa apenas params da query. SQL livre, sem allowlist, sem LIMIT, sem timeout
LG-04 Grounding sources obrigatorio e nao-vazio ao entrar em generate. Prompt anti-alucinacao. Resposta sem fonte, prescrição sem evidencia, sources como lista vazia
LG-05 Interrupt real interrupt_before + MemorySaver para acoes irreversiveis. Retomada via invoke(None). Simular pause com condicional, human-in-loop sem checkpoint, resumo sem thread_id
