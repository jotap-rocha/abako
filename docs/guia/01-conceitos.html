O Problema

Dev sem harness: caos garantido

Sem memória

Cada sessão começa do zero. O agente não sabe o que já foi decidido, qual é a stack, quais são os limites.

Sem limites

Sem guardrails, o LLM pode executar rm -rf, DROP TABLE em produção, ou logar PII sem mascaramento.

Sem gate

Código gerado não é testado. Mypy nunca é rodado. Sessão encerra com vermelho e ninguém sabe.

Consequência real: o agente é poderoso mas não tem julgamento. Sem contexto, sem limites, sem gate — ele vai errar de formas caras.

Definição

Agent Harness: o ambiente que governa o agente

Código do produto — o que você está construindo (FastAPI, pipeline, chatbot). Vive em backend/, src/, frontend/.

Agent Harness — o ambiente que governa como o Claude age. Vive em .claude/. Não é o produto — é o meta-ambiente.

Skills: procedimentos reutilizáveis

O que é uma skill?

Arquivo SKILL.md com instruções passo a passo. O Claude lê e executa como um playbook. Invocado com /nome-da-skill.

Skills de workflow (neste canônico)

/grill-me · /grill-with-docs · /handoff
/harness-architect · /to-issues · /to-prd
/to-tasks · /write-a-skill

Como instalar skills de stack?

Via skills-lock.json na raiz:

{
  "version": "1",
  "skills": {
    "fastapi-templates": {
      "source": "github.com/anthropics/anthropic-skills",
      "sourceType": "github",
      "skillPath": "fastapi-templates",
      "computedHash": ""
    }
  }
}

Caveman — skill da comunidade que comprime o output do Claude para estilo conciso/primitivo. Economiza tokens quando você não precisa de explicações longas.

Agents

Agentes: especialistas com contexto fresco

O que é um agente?

Subagente com contexto fresco. O Claude Code "despacha" para ele quando o trigger no description: combina. Não vê a conversa anterior — começa limpo.

Exemplo: revisor-codigo

---
name: revisor-codigo
description: >-
  Revisor soft do diff. Use após implementar
  uma fatia, antes de commitar.
  Dispare com "revisa esse diff".
tools: Read, Grep, Glob, Bash
color: yellow
---

Comparação

Skills vs Agents — quando usar cada um?

SkillAgent
NaturezaProcedimento / playbookEspecialista autônomo com tools
ContextoVê a conversa atualContexto fresco — não vê o histórico
PersistênciaExecuta e retornaExecuta tarefas complexas multi-step

Use skill quando: a tarefa é um procedimento bem definido com passos fixos. Ex: gerar PRD seguindo um template.

Use agent quando: precisa de especialista isolado, contexto fresco, ou tasks que rodam em paralelo / com tools específicas.

Knowledge Base

KBs e MCP Context-7: memória técnica do projeto

KBs locais (.claude/kb/)

Documentação interna do domínio ou stack. Criada uma vez, referenciada em toda sessão. Exemplo do workshop:

.claude/kb/
├── pipeline/     ← Medallion, contratos, lineage
├── fastapi/      ← routers, middleware, padrões
└── sisfraude/    ← glossário de fraud detection

Crie com: kb-architect (agente)

MCP Context-7

Acesso a docs oficiais de bibliotecas externas em runtime. Sem alucinação de API.

# .mcp.json
{
  "context7": {
    "command": "npx",
    "args": ["-y", "@upstash/context7-mcp"]
  }
}

O kb-architect usa Context-7 para criar e atualizar KBs com docs atuais.

Regra de ouro: KB local = docs do domínio (glossário, regras de negócio). Context-7 = docs da biblioteca (API oficial). Nunca inverter.

Princípios

O que faz o método funcionar

Alinhar antes de gerar

Ideia → grill → PRD → harness → tasks. Nenhuma linha de código antes de resolver o "porquê".

Gates hard

Hook Stop bloqueia a sessão com vermelho. Não comite, não encerra, sem gate verde.

Invariantes como lei

O que está em CLAUDE.md como invariante nunca é flexibilizado. Sem exceção, sem "só dessa vez".

Erro vira sinal

Bug escapado → teste de regressão. Gate falhou → corrija, não silencie. Cada erro endurece o harness.

SI desde o início

SI assessment no passo 0. Não como checklist de compliance — como guardrail real que previne acidentes.

Harness dinâmico

Começa mínimo. O /harness-architect gera o que é necessário para o projeto específico durante o workflow.
