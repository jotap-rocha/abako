Agent Harness Method · 09/09

Agentes de Apoio:
SDD Personalizado + Context-7

Agentes que orquestram o método + um KB que nunca fica desatualizado

harness-brainstorm / define / design / build / ship kb-architect + Context-7 MCP revisor-codigo · agent-creator
O Problema

Overhead cognitivo sem orquestração

Sem agentes de apoio

  • Dev precisa memorizar o fluxo completo do método

  • Pula o /grill-me "porque já sabe o que precisa"

  • Gera PRD sem salvar nos artefatos corretos

  • Não sabe se rodou o /harness-architect

  • Commita sem passar pelo revisor-codigo

  • Esquece de gravar em metrics/entregas.jsonl

Com agentes personalizados

  • Agente conhece o fluxo e guia automaticamente

  • Faz as perguntas certas antes de prosseguir

  • Salva em .claude/projetos/{slug}/ automaticamente

  • Gera o harness como parte do workflow

  • Gate OBRIGATÓRIO antes de cada commit

  • Ship só conclui após scorecard + retro

Princípio: Agentes personalizados não são atalhos — são guardiões do método. Eles tornam impossível pular etapas críticas acidentalmente.

Comparação

Dois métodos, mesma filosofia — diferenças importantes

agentspec SDD é o método genérico. harness-* é a versão personalizada com consciência de SI, detecção de pipeline e gates obrigatórios.

Dimensão agentspec SDD genérico harness-* (personalizado)
Onde salva .claude/design/features/ .claude/projetos/{slug}/
SI awareness Não tem SI assessment no passo 0
Pipeline detection Não tem Detecta tipo e aplica 10 perguntas
Gate obrigatório Não enforça Gate + revisor OBRIGATÓRIOS por task
Scorecard no ship Não tem /scorecard obrigatório + 05-retro.md
Harness gerado Não tem /harness-architect na fase design
Use agentspec SDD em projetos sem harness configurado
Use harness-* em todo projeto com canônico configurado
Fase 0 + 1

O ponto de entrada — captura com consciência

harness-brainstorm

Ponto de entrada do fluxo. Ativado quando user descreve ideia nova.

  • Pergunta 1

    "Qual ideia você quer construir?"

  • Pergunta 2 — SI Assessment

    a) Sem IA / b) IA assistiva / c) Agente autônomo / d) Multi-agente

  • Pergunta 3 — Tipo

    app / pipeline-local / pipeline-cloud / outro

  • Saída

    Deriva slug → cria STATUS.md + 00-ideia.md

harness-define

Após o /grill-me, estrutura os requisitos formalmente.

  • Q&A capturado

    Salva todas as respostas do /grill-me em 01-grill.md

  • Pipeline bias

    Se tipo = pipeline-*: aplica as 10 perguntas obrigatórias antes de fechar

  • Requisitos estruturados

    Funcionais, não-funcionais, restrições, premissas

  • Saída

    Atualiza STATUS.md: fase 1 concluída

Invariante: harness-define só avança se o /grill-me foi completado. Sem Q&A = sem PRD. Sem PRD = sem build.

Fase 2

PRD + harness em uma fase

harness-design — fluxo

1
Lê artefatos anteriores
00-ideia.md + 01-grill.md
2
Roda /to-prd
Gera PRD.md a partir dos requisitos
3
Copia para 02-prd.md
Persiste no projeto slug
4
Roda /harness-architect
Gera o .claude/ específico do projeto
5
Salva 03-harness.md
Decisões de arquitetura + harness gerado

O que /harness-architect gera

  • CLAUDE.md preenchido

    Stack real do projeto, invariantes específicos

  • Agentes de domínio

    pipeline-architect, schema-guardian, etc.

  • KBs da stack

    via kb-architect + Context-7 validados

  • Rules da stack

    pipeline.md, observability.md, etc.

  • .mcp.json

    Stores reais: Postgres, Qdrant, MinIO, etc.

Resultado: Ao fim do harness-design o projeto tem infraestrutura de agente completa, pronta para o build começar com máxima assistência.

Fase 3 + 4

Build com gates + Ship com evidência

harness-build (por task)

1.

Lê tasks/NN-*.md + verifica bloqueadores

2.

Implementa a task

3.

Gate: /validar OBRIGATÓRIO
(ruff + mypy + pytest — verde = pré-requisito)

4.

Revisor: revisor-codigo OBRIGATÓRIO
(nenhum bloqueante em aberto)

5.

Commit: feat(task-NN): titulo

6.

Fecha task + appenda metrics/entregas.jsonl

harness-ship (ao concluir)

1.

Verifica: todas as tasks = done?

2.

Roda /scorecard OBRIGATÓRIO
(métricas reais contra Definição de Pronto)

3.

Escreve 05-retro.md
métricas reais + aprendizados honestos

4.

Fecha STATUS.md: CONCLUÍDO

5.

Commit: chore: ship {slug}

Invariante: Ship só fecha se o scorecard passou. Sem scorecard = feature não entregue.

Agentes auxiliares

Mudanças mid-stream e criação de agentes

harness-iterate

"Requisitos mudaram no meio do caminho"

  • Atualiza o artefato da fase mais cedo afetada

  • Propaga cascata para fases subsequentes

Cascade map

00-ideia → 01-grill → 02-prd → 03-harness → tasks

  • Marca tasks in-progress como needs-review

  • Cria ADR se mudança foi contestável

agent-creator

Cria novos agentes via entrevista estruturada

1. Interview
Propósito, triggers, quando ativar
2. Design
Tools necessárias, comportamento esperado
3. Generate
Gera .md completo com frontmatter correto
4. Save
Salva em .claude/agents/ automaticamente

Quando usar iterate: qualquer mudança de requisito que afeta artefatos já produzidos. Nunca edite artefatos manualmente sem rodar o iterate — a cascata garante consistência.
