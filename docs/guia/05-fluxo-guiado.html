Com /novo-projeto

Cada etapa e salva automaticamente

Grill? Salvo em 01-grill.md. PRD? Em 02-prd.md. Nova sessao: o agente le o STATUS.md e sabe exatamente onde parou.

STATUS.md sempre sincronizado

Cada comando harness-* atualiza a fase e o checklist. Uma linha de verdade sobre o estado do projeto.

Multiplos projetos, zero confusao

Cada projeto tem sua propria pasta em .claude/projetos/. Coexistem sem interferencia.

Inspiracao

Inspirado no Spec Driven Development (SDD)

O harness adapta o workflow SDD do agentspec, adicionando SI assessment, deteccao de pipeline e gates obrigatorios.

SDD (agentspec) Agent Harness Method
/brainstorm → BRAINSTORM_{F}.md harness-brainstorm → 00-ideia.md
/define → DEFINE_{F}.md harness-define → 01-grill.md
/design → DESIGN_{F}.md harness-design → 02-prd.md
(harness setup) /harness-architect → 03-harness.md
/build → BUILD_REPORT_{F}.md harness-build → tasks/*.md
/ship → SHIPPED_{date}.md harness-ship → 05-retro.md

Diferenca principal

harness-* inclui SI assessment (nivel a/b/c/d), deteccao de tipo (web app / pipeline / API), e gates obrigatorios (ruff+mypy+pytest antes de avancar de fase).

Estrutura

A pasta que rastreia cada projeto

# Uma subpasta por projeto

Uma subpasta por projeto

Multiplos projetos coexistem sem interferencia. agente-de-vendas/, fraud-detector/, data-lake-v2/ — cada um com seu proprio ciclo de vida.

STATUS.md e a ancora

Sempre leia o STATUS.md para saber onde esta. Em nova sessao, o agente le o STATUS.md automaticamente e retoma do ponto certo.

Artefatos em ordem cronologica

Prefixos 00 a 05 garantem ordem lexicografica e clareza de progressao. Nunca ha ambiguidade sobre qual veio primeiro.

/novo-projeto → ideia + SI + tipo Cria STATUS.md + 00-ideia.md com SI assessment (nivel a/b/c/d) e tipo detectado (web / pipeline / API)

/grill-me → entrevista implacavel Agente questiona a ideia sem piscar. Perguntas duras sobre viabilidade, escopo, riscos. Pipeline adiciona 10 perguntas extras.
4
harness-define → salva 01-grill.md Persiste o Q&A do grill. Atualiza STATUS.md para fase 1 concluida com timestamp.
5
harness-design → PRD + harness Roda /to-prd e /harness-architect em sequencia. Gera 02-prd.md + 03-harness.md com stack real e invariantes.
6
/to-tasks → tasks atomicas Cria tasks/NN-*.md com criterios de aceite testáveis. Gera 04-tasks-index.md como indice.
7
harness-build → task a task Gate (ruff+mypy+pytest) + revisor-codigo obrigatorios ao fechar cada task. Nenhuma task fecha vermelha.
8
harness-ship → retro + entrega Scorecard, 05-retro.md, STATUS.md marcado como concluido. Delivery record em metrics/entregas.jsonl.
Harness dinamico

Minimo → especifico via /harness-architect

O canonico traz (minimo indispensavel)

  • ‣9 agentes universais (harness-*, revisor, kb-architect)
  • ‣8 skills de workflow (brainstorm → ship)
  • ‣rules: seguranca.md + definicao-de-pronto.md (globais)
  • ‣rules: agente / backend / frontend / pipeline (path-scoped, templates)
  • ‣settings.json com deny list de SI
  • ‣CLAUDE.md com [PLACEHOLDERS] prontos para preencher
→

O /harness-architect gera (especifico do projeto)

  • ‣CLAUDE.md preenchido com stack real + invariantes do produto
  • ‣Agentes de dominio (ex: pipeline-architect, schema-guardian)
  • ‣KBs da stack (ex: .claude/kb/databricks/, .claude/kb/fastapi/)
  • ‣Rules de stack (ex: rules/langgraph.md, rules/pipeline.md)
  • ‣.mcp.json com stores reais (Postgres, Qdrant, MinIO)
  • ‣config/environments/ + pipeline_config.py (se pipeline)

O canonico e intencionalmente generico. O /harness-architect o transforma no harness especifico do seu produto — sem trabalho manual, sem copiar/colar.

Proximos passos para comecar

01

Clone o repositorio

git clone <este-repo> meu-projeto

O canonico ja tem tudo: agentes, skills, rules, settings.json com deny list.

02

Configure o .env

cp .env.example .env

Preencha as chaves reais: OpenAI API key, Anthropic API key, connection strings.

03

Inicie o fluxo

Abra o projeto no Claude Code e diga /novo-projeto. O agente conduz tudo a partir dali.

04

Context7 (opcional)

npx -y @upstash/context7-mcp@latest

Disponivel? Ative para docs live das bibliotecas da stack direto no contexto do agente.

05

Personalize

Siga o guia docs/manuais/como-usar.md para adicionar agentes de dominio, KBs e MCP servers especificos.

06

Monte o harness

Rode /harness-architect para gerar o CLAUDE.md preenchido, regras de stack e agentes de dominio do seu produto.
