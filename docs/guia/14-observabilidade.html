Observabilidade em IA

Langfuse, structured logging, SLOs e alertas

Langfuse structlog SLOs Métricas Alertas

"O que você não mede, você não melhora. Em IA, o que não tem trace, não tem diagnóstico."

O Problema

Por que observabilidade em IA é diferente?

Desafios únicos de LLMs

  • Caixa preta: raciocínio interno invisível, saída imprevisível
  • Custo acumula: cada token custa — sem medição, sem controle
  • Latência varia: p50 bom, p99 péssimo — média engana
  • Alucinação silenciosa: não levanta exceção, não aparece no log
  • Grounding ausente: resposta sem fonte = falha que parece sucesso

Hierarquia de observabilidade

request do usuário
↓ abre [trace] — request inteira ↓ contém [span] — suboperação ↓ inclui [generation] — chamada LLM ↓ recebe [score] — avaliação

Princípio OBS-00

Observabilidade em IA não é opcional — é o único caminho para sair do ciclo "deploy e reza". Sem traces, você está voando cego em produção.

Langfuse

Hierarquia de conceitos

Trace

Request inteira do usuário — do input ao output final. Unidade de observação principal.

Span

Suboperação dentro do trace (ex.: recuperar contexto, executar SQL, montar prompt).

Generation

Chamada ao LLM com tokens prompt/completion, custo estimado e latência.

Score

Avaliação humana ou automatizada. Ex.: grounding 0-1, relevância, correto/errado.

Dataset

Coleção de pares input/expected-output. Alimenta evals automatizadas contra golden dataset em seed/evals/golden/.

Integração

Langfuse + LangChain / LangGraph

from langfuse.callback import CallbackHandler
from langfuse import Langfuse

langfuse = Langfuse()  # lê LANGFUSE_* do env

# Factory — cria handler por sessão
def make_handler(session_id: str) -> CallbackHandler:
    return CallbackHandler(
        session_id=session_id,
        trace_name="agent-run",
    )

# Integrar no grafo LangGraph
async def invoke_graph(query: str, session_id: str):
    handler = make_handler(session_id)
    try:
        result = await app.ainvoke(
            {"query": query},
            config={"callbacks": [handler]},
        )
        return result
    finally:
        # OBRIGATÓRIO — flush antes de encerrar
        langfuse.flush()

O que o handler captura

  • Cada chamada LLM como Generation
  • Tokens prompt + completion
  • Custo estimado por modelo
  • Latência de cada nó do grafo
  • Inputs e outputs de cada step

Anti-padrão: esquecer flush()

O Langfuse envia traces em batch de forma assíncrona. Sem flush() antes de encerrar o processo, traces são perdidos silenciosamente — especialmente em serverless/Lambda.

Logging

Structured logging com structlog

import structlog, contextvars

# Configurar uma vez no startup
structlog.configure(
    processors=[
        structlog.contextvars.merge_contextvars,
        structlog.processors.add_log_level,
        structlog.processors.TimeStamper(fmt="iso"),
        structlog.processors.JSONRenderer(),
    ]
)
log = structlog.get_logger()

# Router — bind por request
async def chat_endpoint(req: ChatRequest):
    structlog.contextvars.clear_contextvars()
    structlog.contextvars.bind_contextvars(
        request_id=req.request_id,
        path="/chat",
        session_id=req.session_id,
    )
    log.info("request.received", query_len=len(req.query))

# Agent node — adiciona contexto de nó
async def classify_node(state):
    log.info("node.classify.start", intent=None)
    # ... lógica
    log.info("node.classify.done", intent=state.intent)

Campos obrigatórios por camada

router

request_id, path, method

service

session_id, user_id

agent

intent, node, latency_ms

Exclusão de PII

Nunca logue conteúdo de query do usuário verbatim. Use hash ou truncate. query[:50] no máximo; campos como CPF, e-mail e senha são proibidos nos logs.

Métricas

Métricas por camada

from dataclasses import dataclass, field
import asyncio, time

@dataclass
class RunMetrics:
    latency_ms: float = field(default=0.0)
    prompt_tokens: int = field(default=0)
    completion_tokens: int = field(default=0)
    estimated_cost_usd: float = field(default=0.0)
    node_timings: dict = field(default_factory=dict)

class MetricsCollector:
    async def measure(self, name: str, coro):
        t0 = time.perf_counter()
        result = await coro
        elapsed = (time.perf_counter() - t0) * 1000
        self.timings[name] = elapsed
        return result

    async def gather(self, tasks: dict):
        return await asyncio.gather(*tasks.values())

# SQL: latência p95 e custo/dia
-- SELECT percentile_cont(0.95) WITHIN GROUP

Onde gravar

  • Schema harness.runs no Postgres
  • Langfuse Generation (tokens + custo)
  • structlog para cada nó do grafo

Custo estimado por modelo

GPT-4o: input * $2.50/1M + output * $10/1M
GPT-4o-mini: input * $0.15/1M + output * $0.60/1M
Calcule no nó generate e grave no trace.

Invariante OBS-02

Todo trace Langfuse deve ter estimated_cost_usd preenchido. Trace sem custo = trace incompleto.

SLOs

Service Level Objectives

Métrica SLI (o que medimos) SLO (target) Alerta
Latência p95 end-to-end ms p95 < 3 000 ms > 3 500 ms
Custo/request USD por run < $0,05 > $0,08
Error rate runs com erro / total < 1% > 2%
Grounding score score Langfuse p50 > 0,80 < 0,65 
from dataclasses import dataclass

@dataclass
class SLOCheck:
    name: str
    metric: float
    target: float
    higher_is_better: bool = False

    def passing(self) -> bool:
        if self.higher_is_better:
            return self.metric >= self.target
        return self.metric <= self.target

SLI vs SLO vs SLA

SLI — o que você mede (p95 latência)

SLO — o target interno (p95 < 3 s)

SLA — contrato com cliente (< 5 s ou desconto)

O SLO é mais restritivo que o SLA — quando viola o SLO, você ainda tem margem antes de violar o SLA.

Invariante OBS-05

SLO definido antes de ir a produção. Sem SLO, não há como saber se o sistema está saudável ou degradado.

Alertas

Alertas e thresholds

import httpx

alert_thresholds = {
    "latency_p95_ms":   (3500, False),  # (limit, higher_ok)
    "cost_per_run_usd": (0.08, False),
    "error_rate":       (0.02, False),
    "grounding_score":  (0.65, True),   # higher = ok
}

async def check_slos(metrics: dict) -> list[str]:
    violations = []
    for name, (limit, higher_ok) in alert_thresholds.items():
        val = metrics.get(name, None)
        if val is None: continue
        breach = val < limit if higher_ok else val > limit
        if breach:
            violations.append(f"{name}={val:.3f} (limit={limit})")
    return violations

async def notify_slack(violations: list[str]):
    if not violations: return
    msg = "*[SLO BREACH]* " + ", ".join(violations)
    async with httpx.AsyncClient() as c:
        await c.post(SLACK_WEBHOOK, json={"text": msg})

Quando alertar vs logar

Alerta = ação humana necessária agora. Ex.: violação de SLO, erro acima de threshold, custo explodiu.

Log = diagnóstico posterior. Ex.: latência acima da média, token count alto, tentativa de retry.

Canais de alerta

  • Slack webhook (síncrono)
  • Email via SendGrid (digest)
  • PagerDuty (on-call crítico)
  • Langfuse alerts (UI config)

Não crie alerta para cada métrica — fadiga de alerta é tão ruim quanto ausência de alerta. Alerte apenas o que exige ação imediata.

Invariantes

Os 5 invariantes de observabilidade

ID Invariante O que proíbe
OBS-01 Toda chamada LLM tem trace Langfuse LLM invocado fora de um trace aberto; handler omitido no grafo
OBS-02 Custo estimado gravado no trace estimated_cost_usd = None no trace; geração sem cálculo de tokens
OBS-03 Log estruturado em toda camada (não print) print() em código de produção; logging.basicConfig sem structlog
OBS-04 flush() antes de encerrar o processo Processo encerrado sem langfuse.flush(); traces parciais perdidos
OBS-05 SLO definido antes de go live Feature em produção sem SLO documentado; threshold de alerta ausente

Como verificar

OBS-01 a OBS-04 são checáveis em code review e nos testes de integração do grafo. OBS-05 é verificado pelo /scorecard antes de fechar a issue — feature sem SLO não passa na Definição de Pronto.
